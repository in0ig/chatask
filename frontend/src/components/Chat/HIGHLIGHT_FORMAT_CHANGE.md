# 文本高亮格式变更说明

## 变更概述

将文本高亮的实现方式从**前端规则匹配**改为**模型输出标记**，确保高亮内容由 AI 模型智能决定，而不是前端写死的规则。

## 变更原因

用户反馈：
> "数字红色 文本是蓝色 跟地区没有关系这里你是的写死的 但是 内容是模型输出的，你要在模型的prompt中告诉模型"

之前的实现问题：
- 前端使用正则表达式匹配数字、百分比、加粗文本等
- 规则写死，无法根据业务语义智能判断哪些内容需要高亮
- 例如：所有数字都会被高亮，但有些数字可能不重要

## 新的实现方式

### 1. 后端 Prompt 配置

在 `backend/src/services/chat_orchestrator.py` 的 `_describe_result` 方法中，添加了格式要求：

```python
⚠️ **重要格式要求**：
- 使用 `<num>数字</num>` 标记所有重要数值（如：<num>12,500</num>元、<num>+13.6%</num>）
- 使用 `<text>文本</text>` 标记所有重要文本（如：<text>上海</text>、<text>进口食品</text>）
- 不要标记普通的连接词、介词等（如"的"、"和"、"在"等）
- 数字包括：金额、百分比、数量、比率等
- 重要文本包括：地区名、产品名、类别名、指标名等关键业务术语
```

### 2. 前端解析逻辑

在 `frontend/src/components/Chat/HighlightedText.vue` 中，简化为只解析标记：

```typescript
const highlightedContent = computed(() => {
  let result = props.content
  
  // 1. 解析模型输出的 <num>数字</num> 标记（红色）
  result = result.replace(/<num>(.*?)<\/num>/g, '<strong class="highlight-number">$1</strong>')
  
  // 2. 解析模型输出的 <text>文本</text> 标记（蓝色）
  result = result.replace(/<text>(.*?)<\/text>/g, '<strong class="highlight-text">$1</strong>')
  
  // 3. 处理换行
  result = result.replace(/\n/g, '<br>')
  
  return result
})
```

### 3. 样式定义

```css
/* 数字高亮 - 红色 */
:deep(.highlight-number) {
  color: #ff4d4f;
  font-weight: 600;
}

/* 文本高亮 - 蓝色 */
:deep(.highlight-text) {
  color: #1154cc;
  font-weight: 600;
}
```

## 优势

1. **智能化**：由 AI 模型根据业务语义决定哪些内容需要高亮
2. **灵活性**：不同场景下可以高亮不同的内容，不受前端规则限制
3. **可维护性**：前端代码更简洁，只负责渲染，不负责判断
4. **准确性**：避免误匹配（如将不重要的数字也高亮）

## 示例对比

### 之前（前端规则）

输入：
```
2023年各商品品类的销售额已通过数据查询得出。具体来看，进口食品的销售额最高，达到XXX元，占总销售额的XX%。
```

问题：
- 所有数字都会被高亮，包括年份"2023"
- 无法判断"进口食品"是否需要高亮

### 现在（模型标记）

模型输出：
```
2023年各商品品类的销售额已通过数据查询得出。具体来看，<text>进口食品</text>的销售额最高，达到<num>XXX元</num>，占总销售额的<num>XX%</num>。
```

优势：
- 模型智能判断"2023"不需要高亮（只是时间背景）
- 模型识别"进口食品"是关键业务术语，需要高亮
- 只有重要的数值被标记

## 测试建议

1. **后端测试**：验证模型是否按照 prompt 要求输出标记
2. **前端测试**：验证 HighlightedText 组件是否正确解析标记
3. **端到端测试**：在实际对话中验证高亮效果

## 注意事项

1. 模型可能不完全遵循格式要求，需要在 prompt 中强调
2. 如果模型输出的标记格式错误（如 `<num>` 没有闭合），前端会原样显示
3. 可以考虑在前端添加容错处理，处理格式错误的标记
